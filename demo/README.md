## 四个视图，一份数据

- **周会工作台** — 会前自动分桶生成议程：升级候选 / 阻塞 / 待客户确认 / 已逾期 / 本周到期 / 7 天未更新。
  一条事项只进一个桶。可一键复制周会纪要草稿与对客周报。
- **纪要回写** — 见下。
- **看板** — 五列状态，「待客户确认」单独成档，等待天数自动计。分组维度可切。
- **甘特** — 细灰条是基线、粗色条是当前计划，两者不齐的地方就是延期痕迹（看 3.1.08 与 3.2.05）。
- **全部事项** — 242 条的统一模型视图，可搜可筛。

点任何视图里的任何一条，打开的都是同一个详情抽屉——同一条记录，不是副本。

## 纪要回写管道

```
STAGE 1 切分与抽取  →  STAGE 2 对齐与匹配  →  STAGE 3 生成字段补丁  →  人工采纳
```

**STAGE 2 是真实实现**（`js/minutes.js`）：显式编号优先（`4.4.29`、`A-002`、`6.1.08`），
匹配不上时退回 CJK 二元组重合度打分，给出置信度与 Top 3 候选。

STAGE 1 与 3 在 Demo 里用确定性规则模拟（日期表达式解析、承诺子句抽取、发言人与责任人区分）。
生产版把这两段换成受 JSON Schema 约束的模型输出即可，**管道形状与人审环节不变**。

内置两份周会纪要，选第一份点「分析并生成补丁」，会得到 10 条命中更新加 1 条新事项候选。
文本框可直接编辑再分析。

四条工程约束在代码里是硬的：

- **AI 不写库** — `applyPatch()` 只在用户点采纳时执行
- **幂等** — `appliedPatches[会议ID#事项#片段]` 去重，同一份纪要重复导入不会重复写
- **留痕** — 每次写入记录来源会议、原文片段与时间，抽屉里可回看
- **不自动改期** — 日期变更不进批量采纳

## 规则引擎

`js/rules.js` 里十条规则每条都标了明细表出处：

| 规则 | 触发 | 依据 |
| --- | --- | --- |
| R1 | 连续 2 次周会未闭环 → 升 L2 | 5.3.1 |
| R3 | 涉范围/工期/费用，禁止会上直接闭环，强制生成 CR | 5.3.3 |
| R4 | 待澄清问题按需求确认书出具日倒排工作日 | 4.4 |
| R7 | 待客户确认项自动计等待天数 | 6.3 / 7.6.3 |
| R9 | 在办事项 7 天无更新自动进议程 | 5.1.1 |

**试一下 R3**：打开任意里程碑，把状态改成「已闭环」——会被拦下并问你要不要生成 CR 草稿。
这就是把「不在会上口头拍板」变成代码。

## 数据落在哪

`localStorage` 的 `kehu.workbench.v1`。「重置」恢复种子数据。

## 文件

```
index.html      壳与视图切换
css/app.css     设计令牌与全部样式（沿用提案页配色）
js/data.js      242 条种子数据（由 xlsx 自动生成）
js/rules.js     规则引擎：议程分桶、健康度、十条治理规则
js/minutes.js   纪要回写三段管道
js/app.js       视图层：四视图 + 详情抽屉 + 导出
```

## 这个 Demo 不包含

工时成本核算、客户账号体系、语音转写、与任何业务系统的对接、百分比进度汇总。
理由见提案第 12 节。
